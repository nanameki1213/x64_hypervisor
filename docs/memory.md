# メモリ

## 物理メモリの分割

HV が持つ物理メモリは次の 2 つだけで、残りはすべて管理 VM に渡す（`hypervisor/src/mm.rs`）。

| 領域 | 範囲 | 用途 |
|---|---|---|
| HV のイメージ | ロード先（2MiB アライン）から、イメージの末尾を 2MiB に切り上げたところまで | コード、データ、bss（ブート用ページテーブル、スタック、GDT / IDT / TSS） |
| HV のヒープ | `HV_HEAP_SIZE`（32MiB）。ConventionalMemory のうち、もっとも高位で直接マップに収まる 2MiB アラインの領域 | VMXON 領域、VMCS、MSR ビットマップ、EPT のページテーブルなど、HV の動的な確保すべて |

- ヒープを高位から取るのは、管理 VM の低位メモリ（リアルモードのトランポリンなど）と競合させないため
- どちらも 2MiB アラインにしてあるので、管理 VM の EPT では周囲を 2MiB ページのままマップできる
- これらの範囲は `MemoryLayout::reserved()` で取得できる。管理 VM に渡す e820 ではこの範囲を reserved にする（#6）
- 起動時に `[mm] image ..., heap ..., memory map top ...` として HV のログに出る

## HV の仮想アドレス空間

HV は自分専用のページテーブル（`boot.S` の `boot_pml4`）で動く。ゲストとは共有しない。

| 仮想アドレス | 物理アドレス | ページサイズ | 用途 |
|---|---|---|---|
| `0` 〜 `512GiB`（`DIRECT_MAP_END`） | 同じ（恒等マップ） | 1GiB | 物理メモリの直接マップ。ヒープ、ページテーブル、ACPI テーブル、ゲストのメモリへのアクセス |
| `0xffffffff81000000` 〜（リンクアドレス） | HV のイメージのロード先 | 2MiB | HV のイメージ |

- 低位を恒等マップにしているので、ヒープから確保したアドレスはそのまま物理アドレスとして VMCS や EPT に書ける
- ページテーブル上はすべて WB だが、MMIO 領域は MTRR によって UC になる
- 制限
  - 512GiB より上の物理メモリには HV からアクセスできない
  - HV のヒープは 32MiB 固定。フェーズ 2 でユーザ VM を作るときに見直す

## 管理 VM の EPT

`hypervisor/src/arch/x86_64/vmx/ept.rs`

- **恒等マップ**（ゲスト物理アドレス = ホスト物理アドレス）。パススルーしたデバイスの DMA がそのまま正しいアドレスに届く
- **HV のメモリ（holes）はマップしない**。管理 VM がアクセスすると EPT violation になり、`[vmx] guest accessed HV memory` を出してゲストを止める
  - DMA による HV のメモリへのアクセスは EPT では防げない。VT-d で保護する（#11）
- **起動時にマップする範囲**: 下位 4GiB（MMIO を含む）と、UEFI のメモリマップに載っている範囲の上端まで
- **遅延マップ**: それより上（64bit BAR など）は、EPT violation が起きたときに、そのアドレスを含む 1GiB を恒等マップする
- **ページサイズ**: holes にかからず、メモリタイプが一様な範囲で最大のもの（1GiB → 2MiB → 4KiB）を選ぶ。1MiB 未満は固定範囲 MTRR でタイプが混在するので 4KiB になる
- **メモリタイプ**: EPT を有効にすると、ゲストのアクセスには MTRR ではなく EPT のメモリタイプが使われる。そのため、物理 MTRR（`arch/x86_64/mtrr.rs`）から求めたタイプを EPT のリーフに設定する。IPAT = 0 なので、ゲストの PAT はそのまま効く
- **無効化**: マップを変更したら INVEPT（single-context、なければ all-context）を実行する

### 注意点・今後の課題

- ゲストによる MTRR の書き換えは捕捉していない。EPT のメモリタイプはマップした時点の MTRR から決めるので、ゲストが MTRR を変えても反映されない。最近の Linux は PAT を使い、起動後に MTRR を変えないので当面は問題ないと考えている（#10 で再検討）
- 権限を絞ったマップ（syscall フックの実行フックなど、#13）には、大きいページを分割する処理が必要。今は未実装
- フェーズ 2 でユーザ VM を作るときは、VM ごとに `Ept` のインスタンスを持つ。複数の vCPU で 1 つの EPT を共有する形は #8 で整理する

## unrestricted guest

EPT とあわせて unrestricted guest を有効にしている。AP をリアルモードから起動する（#8）のに必要なため。

- ゲストは CR0.PE / PG を自由に切り替えられる。CR0 / CR4 のうち VMX で固定されたビット（NE、VMXE など）は、実際のレジスタでは強制し、ゲストには書いた値を見せる
- ゲストが CR0.PG を切り替えて IA-32e モードを出入りしても、VM-entry の "IA-32e mode guest" は自動では更新されない。VM entry の前に EFER.LMA に合わせて更新している
